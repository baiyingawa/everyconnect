# EveryConnect 路线图

EveryConnect 的长期目标是让 DSH 的工作区、任务会话、模型和工具能够通过多个聊天平台使用。首个连接器是微信 Claw/iLink，后续计划接入 QQ 机器人、企业微信及其他 AI 信息支持平台。

## 已完成

- 微信二维码登录、持久化凭证和过期恢复。
- iLink `getupdates` 长轮询、文本解析、去重、回复和输入中状态。
- 工作区-任务会话菜单、分页、模型设置、配置统计和 `/stop`。
- `/new workspace` 创建目录并登记工作区，`/new task` 创建任务并自动进入。
- Web 设置页、二维码显示、连接状态和二次开发 desktop loader 兼容。
- 同一来源串行、不同来源并行的消息队列。

## 下一阶段：稳定化

- 建立 DSH Runtime 版本兼容矩阵。
- 增加轮询耗时、消息去重、发送失败和登录过期指标。
- 补充日志脱敏测试，覆盖 token、二维码和 context token。
- 明确群聊、非文本消息和超长文本行为。
- 建立可手动触发的真实微信 smoke test。

## QQ 机器人

计划先实现文本消息闭环：平台登录、私聊/群聊事件、消息 ID 去重、回复引用和可取消的 WebSocket 或事件回调生命周期。QQ 专用字段只应留在 `src/qq/`，统一复用 EveryConnect 的菜单、会话设置和 DSH 路由。

## 企业微信

计划先实现企业内部应用或机器人文本消息：回调验签、事件解密、重试去重、access token 缓存刷新和回调服务器生命周期。凭证和签名密钥始终由 Host 管理，Client 只展示非敏感连接状态。

## 富媒体与多账号

- 图片、文件、语音的统一附件模型。
- 多账号选择和账号级 allowlist/denylist。
- 各平台 Markdown 子集和大小限制转换。
- 更完整的任务进度、停止状态和连接诊断。

## 工程原则

- 协议层使用 fake transport 测试，默认测试不访问真实网络。
- 所有 IO 可取消，所有后台任务随 Host 生命周期结束。
- 新平台新增 adapter 和测试，不复制 DSH Router 与菜单状态机。
